# Three-minute demo plan

Use fictional data. Rehearse a genuine live run and have a clearly labeled saved audit ready if the API is unavailable. Never present replay as live inference.

| Time | On screen | Message |
|---|---|---|
| 0:00–0:25 | Healthcare case and review objective | A transport request is only useful when the pickup, vehicle and return plan are coordinated. |
| 0:25–1:20 | Live Meta tools, document observations, exact facts | The model investigates; code verifies. Show one receipt and a source citation. |
| 1:20–1:55 | Missing-return or unsafe-curb case | The agent stops when evidence cannot support a booking. |
| 1:55–2:25 | Memo and human review | Reviewers can inspect every source and the independent checks before acknowledgment. |
| 2:25–3:00 | Audit export and boundaries | Explain new event work, live Meta versus simulated curb data, and the proposed clinic-coordinator pilot. |

Potential pilot measurements: coordinator minutes per reviewed request; incomplete requests detected before handoff; pickup issues resolved; rider-reported experience. These are proposed measurements, not results.

Before a real healthcare pilot, design staff authentication, least-privilege access, transport-provider agreements, privacy review, data retention, appropriate vendor arrangements and operational escalation with the participating organization. Keep clinical decisions with qualified staff.
